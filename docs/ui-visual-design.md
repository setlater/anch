# UI 视觉设计

## 实施基线

安册采用已确认的「石墨资料册」方向，以 [资料册 HTML Demo](../design/prototype/anch-ui-editorial-demo.html) 的石墨配色与内容优先布局为参考。它替代旧白瓷档案和雾青基线；旧 HTML 样张保留作历史参考，不再约束实现。正式 UI 不提供样张里的配色选择器、虚构资料、浏览器尺寸控件或评审说明。

以 Android 交互为基础，参考 Apple 的信息分组与排版，以及 Material 3 的语义色、操作层级和窗口适配。界面首先服务于快速查找、安全查看与复制、可靠备份和重要日期提醒。不得改变已经确认的产品边界、录入顺序和安全行为。

参考：[Apple 布局](https://developer.apple.com/design/human-interface-guidelines/layout) 、[Apple 排版](https://developer.apple.com/design/human-interface-guidelines/typography) 、[Material 3 配色](https://developer.android.com/design/ui/mobile/guides/styles/color) 与 [Android 自适应窗口](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes) 。完成状态只在 `ROADMAP.md` 维护。

## 视觉原则

- 背景、正文、辅助文字和资料图标使用中性色。石墨强调色表达操作、焦点与选中，成功、到期和危险状态保留各自独立语义。
- 首页紧凑组合标题和数量，新增放在页头。常规到期事项使用分组标题行内的文字入口，临近到期、今日到期与已过期仍清楚提示，不能为了减重隐藏风险。
- 置顶与普通资料共用摘要组件，以同一种列表行和分组表面区分；不重复展示同一资料。
- 只读字段使用分组表面；输入项使用独立边界和明确焦点反馈，不嵌套相同白色卡片。
- 分组标题通过文字、留白和对齐表达，不再增加册脊色块或装饰线。
- 不引入渐变、玻璃拟态、发光、彩色阴影、大面积插画、特殊展示字体或营销式口号。

## 排版与布局

- 页头主标题 28，详情正文标题 24，子页工具栏标题 18，资料名称 17，正文及输入 16，归属、标签与分组标题 14，辅助说明 12～13。以常规、中等和半粗字重建立层级，不把所有文字都加粗。
- 使用系统字体与已有 Solar 图标，不额外引入字体或图标依赖。中文字号增大时保持层级，不能压缩关键内容或裁切姓名、号码、地址和操作。
- 手机页面边距使用共享间距；常规与扩展窗口依据可用空间调整。表单和详情阅读宽度最多 640，资料列表最多 840。
- 输入圆角 8，搜索与页头新增 12，资料／字段／号码分组 14，选择项和模态容器 16；主要流程按钮可以使用胶囊。普通资料行本身不叠加独立阴影。
- 所有按钮和可操作图标保持至少 48 的触控范围。普通资料行最小高度约 76，并随内容与字体自然增长。
- 以窗口宽度判断紧凑、常规、扩展结构，同时考虑键盘与可用高度。窄屏、大字体下字段轨道、日期和操作组改为纵向，不能按机型分支。
- 扩展窗口的主导航使用侧边结构，紧凑窗口保留底部导航。旋转与窗口变化时保留当前页面、筛选和录入内容。
- 底部导航图标独立居中并固定为 22，标签保持 12；选中项不加背景色，通过图标变体、石墨前景和文字字重区分，整项触控高度至少 48。

## 组件与页面

### 首页与列表

- 搜索先于资料，事实性短提示即可。页头使用紧凑标题、数量和明确新增入口，不再显示营销副标题或另外叠加悬浮新增。
- 置顶资料先展示，其余资料使用同一摘要行，归属与必要的低敏摘要可自然换行。全量入口与现有排序、筛选、刷新、失败重试和请求防乱序行为保持。
- 银行卡列表摘要只保留归属与银行名称，注销状态独立显示；用途与完整补充信息在详情中保留，不通过省略关键值压缩列表。
- 普通常规到期提醒为文字入口，紧急状态保留危险语义与明确数量。真实空数据和加载失败必须区分。
- 成员使用共享头像，系统家庭与我保留语义图标；其他成员使用首个可见字符。成员根页和分类根页的新增资料也放在页头；成员新增和编辑能力保持。
- 分类继续消费唯一模板来源，可按可用空间显示索引或列表；不增加独立类别定义。
- 分类网格保留横纵间距；设置状态在标题可完整横排时靠右，空间不足时移到说明下方，避免挤窄标题与说明。
- 搜索结果优先展示匹配数量与资料；筛选分组默认收起，入口保留已选条件数量。展开时收起键盘，收起分组保留条件，换关键词重置条件与展开状态；窄屏和大字号允许数量与入口换行。
- 搜索空白引导按剩余高度居中，键盘、短窗口和大字号下允许滚动，不以固定上下留白挤出说明。

### 详情与敏感号码

- 标题、资料类型与归属建立身份层级；标题图标对齐首行，标签由一个 `Wrap` 管理，避免重复留白和重复分类。
- 号码使用与其他字段相同的表面，不叠加品牌色标题底块、装饰色条和阴影。压缩无效留白，查看与复制同级并保持至少 48 的操作高度。
- 关键值不得用 `FittedBox` 缩到不可读；长号码、大字体允许自然换行。显隐切换保留布局稳定和原有页面退出／锁定／后台清理行为。
- 顶部号码复制先确认，确认框只显示待复制内容；字段行直接复制。银行卡菜单仍只有「仅复制卡号」「复制完整信息」「取消」，信用卡完整信息不含有效期。
- 只读字段按标签／值／操作轨道分组，窄屏与大字体重排；所有敏感字段白名单、遮蔽、认证和复制清理策略保持。
- 常规手机宽度下短字段保持标签与值同行，避免过早纵排造成大块留白；顶部操作菜单使用「更多操作」图标与无障碍名称，铅笔只表达编辑。
- 详情按标题、号码、资料字段、附件与操作记录组织；附件缩略图与添加入口沿用一致尺寸及已有加密／预览行为，不引入敏感内容动效。
- 图片读取或解码失败后提供至少 48 高的「重新加载」，只在用户点击时重试当前图片；缓存预览解码失败时移除对应的派生磁盘缓存，清理结束后允许重试原图，重新打开时按需重建预览。读取与解码完成前禁用保存，失败时清零对应内存缓存，后台或退出后丢弃并清零晚到结果，不展示异常原文或物理路径。

### 新增与编辑

- 保留「类型 → 归属 → 填写 → 补充」四步，成员入口可预选归属；编辑和历史模板兼容保持。类型、归属选择不能单独触发丢弃内容警告。
- 步骤使用用户语言，取消重复「本地保存」说明；键盘和短窗口下进度保持清晰且内容可滚动。
- 类型网格与页面使用一致边距和卡片间距；紧凑选项不预留透明勾选位，选中标记复用前导图标位置，避免挤压名称或改变选中前后的文字宽度。
- 紧凑类型卡片采用图标在上、名称在下的排列，为完整类型名称提供宽度；填写区使用紧凑标题与说明，键盘弹出时收起重复标题说明。性别选项至少 48 高并随文字自然增长，日期输入显示日历图标与选择提示。
- 标签常态中性，输入独立描边；聚焦时文字与边界反馈，错误使用危险语义。日期与并排字段使用现有自适应布局。
- 身份证地址与收货详细地址共用两至三行输入，长内容自然换行，超过三行可纵向滚动；收件人、手机号码与地区保持原有字段行为。
- 只在实际改动字段、备注、附件或户口成员时提示放弃；保留自动填充、字段来源、验证、动态增删、长期日期与提交行为。
- 补充页附件说明仍为「附件保存在应用内部，不进入系统相册」。

### 设置、安全与备份

- 设置、应用锁、屏幕保护、归档、最近删除和备份统一消费石墨主题与文字层级；不增加说明页或操作层级。
- 设置页优先展示安全与数据操作，本机离线保存说明压缩为页尾的一句辅助文字。
- 数据与备份直接提供导出和恢复；执行前展示范围、密码后果、覆盖语义和失败保护。认证、清单、staging、原子切换与清理保持。
- 备份页系统栏前景随当前亮暗主题变化；密码长度要求独立显示并允许换行，不依赖单行输入占位提示。
- 导出与恢复密码页在键盘展开且安全区内剩余高度不足 200 个逻辑像素时临时收起顶部栏，为密码内容和操作保留滚动空间；收起键盘后恢复标题与返回入口，切换过程中保留输入焦点。
- 居中轻反馈与共享全屏进度遮罩保持。长操作不能提前显示 100％，失败不能显示成功。
- 临时浮层显式建立 Material 文字边界；只显示脱敏阶段，不展示路径、密码、密钥或敏感内容。

## 图标、返回与动效

- 图标固定使用本地 Solar 1.2.5，经 `AnchIcons` 与 `AnchIcon` 统一映射和渲染；不在页面直接拼路径或混入其他库。
- 类型图标默认中性色；操作和导航选中使用石墨强调色。图形的视觉重量需与相邻文字匹配，不在渲染器暗中缩放个别资源。
- 来源与许可见 `design/prototype/assets/solar/1.2.5/NOTICE.md`。
- 返回继续复用 `AnchRouteBack`；编辑、关闭等工具栏操作复用 `AnchHeaderAction`。新增可用同一语义图标的文字按钮。触控区不得遮挡标题，长标题和大字体下操作换行。
- 返回只负责离开，保存、丢弃、关闭流程保留独立明确行为；`PopScope` 的安全与业务拦截不放宽。
- Android 保留系统默认转场和预测返回能力；敏感内容不增加 Hero 或变形动画。减少动态效果时关闭非必要动效，不增加弹跳、强模糊或营销动效。

## 验证与边界

- 不修改数据库 schema、迁移、资料状态、备份格式、安全策略、权限、依赖或发布配置。
- 截图与视觉检查只使用隔离夹具或明确仅含虚构资料的验证状态，不读取或截图真机现有资料。
- 必须通过静态分析、完整自动化，以及紧凑／常规／扩展宽度、暗色、大字体和短高度回归。检查文字、状态和主要操作的对比度。
- 按项目规范构建内部验证 APK，并在每次部署前重新检查设备；构建与自动化通过不能替代真机体验和正式安全准入。
