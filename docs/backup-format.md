# 备份与恢复格式

## 格式状态

Android 默认导出使用流式 V3。V2 是历史流式格式，V1 是历史整包格式，两者保留导入兼容；V1 不再作为大附件容量的扩展路径。

### V3：当前默认格式

V3 沿用 V2 的分帧认证结构，直接通过 Android SAF 顺序写入和读取，公开头用版本号和 `portablePlaintext` 标识附件编码。

- 公开头只包含格式版本、PBKDF2 参数、随机 salt、分帧 nonce 前缀、算法和压缩标识；不包含成员名称、资料摘要、附件名称、密码或密钥。
- 每个资料清单或附件数据帧独立使用 AES-256-GCM 认证；AAD 绑定公开头、帧类型、顺序、附件序号和长度。
- manifest 在加密前 gzip 压缩；附件原文仅在内存短暂解密并直接交给备份密码保护的认证帧，不落盘、不重复压缩。恢复时在 staging 中以当前本机密钥重新加密，支持清空本机密钥或换设备后的恢复。
- 最终提交帧认证数据帧数、manifest 字节数、附件累计字节数和附件数。缺少最终提交帧、帧顺序错误、认证失败或累计长度不符的文件一律不可恢复。
- 容器按规范化后的清单顺序、以附件 ID 解析字节来源；即使调用方传入未排序的清单，也不得将附件帧绑定到其他附件的元数据。输入列表和来源 map 的插入顺序不决定恢复归属。
- manifest 压缩前、后安全处理上限均为 64 MiB；它不限制附件总量，超过上限必须安全失败，不得耗尽内存或跳过内容。
- 新导出默认文件名为 `anch-YYYYMMDD-HHMMSS.abk`；恢复选择器与文件名校验继续兼容历史 `anch-backup-YYYYMMDD-HHMMSS.abk` 文件名。

容量策略与真机验证状态以 `ROADMAP.md` 为准。导出前根据已知输入和帧开销给出保守估算，估算值超过当前提示阈值 240 MiB 时，必须向用户提示耗时与目标位置空间风险，但仍允许继续。恢复时已知文件大小超过该值时同样提示，不得仅因此拒绝恢复；旧 V2 的容量验证不能直接当作 V3 的完整真机结论。SAF 目标位置没有通用可靠的剩余空间查询；实际空间或 I/O 失败必须安全失败。未完成的外部文件没有最终提交帧，应用不自动删除。

### V2：历史流式兼容

V2 的附件帧保存原本机密钥加密的附件字节，再由备份密码保护。恢复时必须验证这些附件能被当前本机密钥解密；无法解密时在正式附件目录和数据库切换前拒绝，不导入不可用附件。不得将 V2 误认为能独立于原设备密钥恢复的备份。

### V1：历史导入兼容

V1 为整包内存编解码格式：

```text
JSON Envelope
├── magic / version / createdAt
├── KDF: PBKDF2-HMAC-SHA256
├── Cipher: AES-256-GCM
├── ciphertext
└── MAC
```

V1 的 salt 与 nonce 每次随机生成，备份密码不保存且无法找回。它适合小规模历史备份导入；当前不增加 V1 的容量能力或新导出分支。

## 数据范围

进入备份：

- 成员、资料、字段、子项及子字段。
- 受备份密码保护的附件内容及附件元数据；V3 恢复时重新使用当前本机密钥加密。
- 最近删除资料、资料生命周期事件和低敏结构化变更摘要。
- 当前／已归档／最近删除状态及删除前 `active／archived` 收纳状态。
- 资料和附件用于可靠同源判断的 `originId`／`originAttachmentId`。
- 模板和数据库 schema 版本信息。

不进入备份：

- AppLock PIN、生物识别状态、数据库主密钥和设备安全凭据。
- 激活凭据与最近查看等设备行为状态。

资料事件包含事件 ID、资料 ID、动作类型和发生时间。归档与取消归档使用明确事件类型。变更摘要只允许保存归属、分类、类型、状态、置顶和 none／low 日期字段的受策略保护信息；标题、备注、普通文本和中高敏字段只保留字段名称，附件只保留添加／移除数量，不包含名称、内容或路径。永久删除资料及其事件不进入之后导出的备份。

用户确认密码并发起导出后，系统文件选择器仍负责选择保存位置。选择器确认并成功打开目标写入会话后，导出页面才显示不可关闭的全屏进度遮罩，阻断页面点击、重复导出、顶部返回和系统返回；用户在选择器中取消时不得闪现遮罩。进度以流式容器实际写入字节占本次精确输出字节的比例计算，原生端完成关闭、长度复核与保存确认前最多显示 99%，只有保存确认成功后才可到达 100%。遮罩只显示脱敏阶段说明和百分比，不显示资料名、附件名、路径、密码或密钥；导出成功或失败后必须先移除遮罩，再显示对应结果。

容量估算与实际导出在打开系统保存位置前都须检查附件来源。准备清单或后续预检发现附件缺失、大小不符等问题时，统一保留不可用附件明细，供失败页面按资料和原因汇总；不得只显示通用失败提示，也不得静默省略附件。失败不更新成功备份历史，不暴露本机文件名或完整路径。

密码校验通过后，容量估算、风险确认和导出属于同一次提交，期间禁止重复启动估算或导出。取消风险确认后可重新提交，密码输入保持；实际保存会话建立前不显示写入进度遮罩。

导出页的结果、容量确认和安全提示弹窗使用页面所在的受保护导航器，不能绕过应用锁出现在根层。回前台需要重新解锁时，附件失败明细与提示按钮均须被锁页遮蔽；解锁后才允许查看和关闭弹窗，关闭后保留导出页。

附件来源流的读取块只由底层 I/O 决定，不构成流式容器帧边界。编码器必须跨读取块连续组装最多 `256 KiB` 的固定上限明文帧，每个附件只允许最后一帧不足上限；因此帧数始终由附件声明的精确负荷长度唯一确定，不能因设备、文件系统或读取缓冲大小变化而改变输出长度或进度总量。组帧缓冲最多保留一个明文帧，来源长度不符仍须在最终提交前整体失败。

## 恢复语义

恢复始终是整包覆盖，不提供逐条选择、合并或冲突处理。

```text
选择备份文件
→ 输入一次备份密码
→ V1 解密校验，或 V2／V3 只读取并认证开头的加密 manifest
→ 展示受限内容清单
→ 用户确认整包覆盖
→ V2／V3 流式读取、完整认证、附件 staging
→ 原子切换附件与数据库事务
```

内容清单仅在当前前台会话展示成员、资料标题、类型、当前／已归档／最近删除状态和附件数量；不得显示字段值、备注、附件名称／内容、路径、密码或密钥。流式清单预览仅证明 manifest 帧可由该密码认证，不能证明附件和最终提交帧完整；预览阶段不创建 staging、不写数据库。用户确认后才完整读取文件、校验附件和最终提交帧并写入 staging，过程显示按实际读取字节计算的进度。取消、页面退出或进入后台时必须清除已认证载荷和 staging，随后需要重新选择文件。确认覆盖后显示不可关闭加载遮罩，阻断重复操作与返回，直至成功或失败反馈出现。

密码认证失败时只清空本次密码输入，不清除用户已经选择的加密备份文件，允许在同一前台恢复会话继续输入密码。V1 复用已准备的有限加密字节；流式恢复只在内存中暂存本次 SAF 选择的 URI，并重新打开同一只读流，不持久化、不显示或记录 URI，也不缓存整份文件。文件格式错误、版本不支持、读取失败、用户切换文件、取消恢复、页面退出或进入后台时仍须立即清除所选文件会话、已认证载荷和 staging。

流式会话清理先同步使当前会话失效、移除已认证内容，再异步关闭输入与 staging。清理期间晚到的文件打开、认证或重开结果不得重新建立恢复状态；后续文件准备须等待此前清理结束。完整认证完成后、进入覆盖事务前仍须确认会话有效，失效结果清理 staging 并拒绝覆盖。

恢复清单与覆盖确认弹窗使用恢复页所在的受保护导航器，后台清理也须关闭同一导航器中的敏感弹窗并保留恢复页，不能退出恢复页却留下清单，也不能让弹窗越过应用锁。安全提示关闭后，原恢复页须要求重新选择文件并输入密码。

V1 兼容路径同样在清理、重新选择或交出加密字节时使此前会话失效。晚到的文件读取、流式格式识别及密码认证结果不得重新缓存文件、启动后续流式会话或返回已认证内容清单。

附件先写入与正式目录同级的 staging 目录，并校验来源、文件名、加密字节和长度。目录切换前写入仅含随机操作标识的恢复日志；数据库事务最后一步写入同一标识的内部提交标记。启动时发现恢复日志：标记存在则保留新附件并清理旧目录，标记不存在则恢复旧附件目录。日志异常或恢复现场缺失时阻断启动，不猜测或删除现有附件。

数据库提交后，只有旧附件回滚副本和恢复日志均已清理，才能移除数据库提交标记。清理失败时保留日志与标记，下次启动继续按已提交状态保留新附件并重试清理，不能将新数据库与旧附件重新组合。

任一可捕获失败必须保留恢复前数据库与附件，不得留下部分恢复状态。流式恢复只有完整认证、顺序和累计字节校验、最终提交帧和 staging 都通过后，才能进入原子覆盖阶段。

## 兼容与载荷校验

- Envelope／容器和 Payload 版本显式记录；导出的 `schemaVersion` 与当前 `AppDatabase.schemaVersion` 使用同一版本来源。
- 旧版本载荷先在内存中通过独立迁移器转换为当前规范，再校验引用完整性并写入数据库；不在反序列化中静默猜测。
- 历史载荷缺少事件或事件变更集合时按空列表迁移，不伪造历史。V1～V7 已删除资料缺少删除前收纳状态时补为 `active`；V8 及更早载荷缺少来源标识时分别按资料／附件原主键补齐；当前 schema 载荷中的来源标识非法或冲突时拒绝。
- 恢复前拒绝未知事件、非法状态组合、重复 ID、缺失引用、非法变更值结构，以及试图为普通文本或中高敏字段注入历史值的载荷。
- 当前版本导出的同版本备份必须可恢复；旧版本备份经迁移后可恢复；未来版本必须整体拒绝，不得降级或部分恢复。
- 改变加密算法、附件编码或载荷字段语义时必须升级格式版本，并补充旧版样本、载荷迁移和 Android 文件提供方回归。
