# 测试策略

## 目标

外部开发者先按 [贡献说明](../CONTRIBUTING.md) 使用显式 contributor 入口；本文固定签名的构建步骤属于维护者内部验证。贡献者包不替代内部验证包或正式发行物。

测试保护真实风险，而不是累计数量。

- 日常反馈目标：10 秒内。
- 提交前核心套件目标：20 秒内。
- 完整自动化不设固定时长目标，记录实际耗时，保留必要覆盖。
- 测试通过时零 warning、零调试输出、零共享资源泄漏。

## 首发设备范围

首发使用现有一加 3T 与一加 12，不要求额外购买或借用设备，也不按设备数量、厂商数量或每台固定资料条数设门槛。报告须区分设备、Android 版本、包类型与实际检查项。

| 设备与系统 | 实际包类型及验证边界 |
| --- | --- |
| 一加 3T／Android 8.0 | 正常正式签名 Release 的覆盖升级、附件跨重启读取、PIN 与受保护弹窗、屏幕保护及 V3 导出；另在独立贡献者安装中完成恢复与读回。 |
| 一加 12／Android 16 | 内部 Debug／Profile 和加密贡献者包的核心体验、展示与性能检查；另以正常生产入口、正式安全模式及正式签名的独立 Release 验收包完成实际强指纹、物理清空／重建、V3 恢复及跨重启读回。独立包与同批正常正式包运行二进制一致，但不覆盖原应用身份的升级路径。 |

不同包类型、应用标识或源码输入的结果不能直接互相替代；后续 UI 变更仅在相关逻辑未变时复用既有安全证据。各项具体结果与未覆盖范围以 [路线图](../ROADMAP.md) 为准。

其他厂商、平板、完整分屏与字号矩阵放入后续兼容性队列。保留紧凑／常规／扩展宽度等现有自动化回归；已知安全缺陷、核心流程失败或关键内容及操作不可访问仍须修复。安装要求只说明可安装条件，不承诺所有满足条件的设备均已验证。

连续体验按风险选择代表资料和操作，已有有效证据可以复用，只补受改动影响或明确缺失的检查；不为凑条数重复录入。不具备条件的安全验证单独保留状态，不能以缩小设备范围替代验证。

## 分层

```text
test/unit/         纯业务规则、模型、模板、校验和密码学边界
test/widget/       单页关键交互
test/integration/  少量完整用户路径
test/security/     AppLock、防窥、密钥、备份与权限
test/platform/     MethodChannel、Manifest、加密数据库
test/support/      Fake、fixture 和统一 bootstrap
test/contracts/    主题角色契约与既有资料展示契约辅助
benchmark/         性能与规模测试，不进入默认套件
```

测试及辅助代码按职责归位，根目录不再放平铺测试；修改文件位置时同步修正测试、基准和工具的相对导入。迁移不得减少测试发现数量或删除独有回归。

默认 `flutter analyze` 覆盖应用、测试、工具与基准源码，排除 `build/` 中的生成物和冻结验证输入。复跑历史夹具时创建与当前接口匹配的新输入，保留原输入和产物；新夹具按文件显式检查并构建，不将旧源码副本并入当前应用检查。

## 标签

标签在根目录 `dart_test.yaml` 声明，不排除任何默认测试；标签附在显式 `library;` 指令上。安全回归使用 `@Tags(['security'])` 标记，密码学、恢复原子性和敏感页面生命周期回归即使位于单元或 Widget 目录也保留安全标签。

- `slow`：超过普通单元或 Widget 测试合理耗时。
- `integration`：跨多个页面或服务。
- `security`：安全准入关键路径。
- `platform`：依赖平台或文件数据库。
- `benchmark`：性能结果，不属于正确性测试。

## 覆盖原则

- 屏幕保护须覆盖平台确认前敏感内容不可见、平台异常后原内容与操作被阻断、启动失败不读取安全存储、显式重试恢复草稿，以及旧请求未完成时不误报新页面已受保护；同时保留三档偏好、PIN 和后台返回的正常行为。故障注入证明异常分支，不冒充真机自然故障或泄露证据。
- 模板差异使用参数化单元测试，不为每种模板重复启动整页。
- 列表异步回归使用可控 Future，覆盖首次失败重试、刷新失败保留内容、旧失败晚于新成功、旧成功晚于新失败与退出后返回；查询回归验证成员／类型交集、排序、收纳状态和数量统计。不得靠真实延时制造竞态。
- 卡片测试只检查实际渲染链，包含紧凑／常规／扩展宽度、真实输入的敏感字段排除及历史保险低敏摘要；不为断言生成第二套 DTO。生命周期和重复操作测试通过真实修改前后的内容与数量验证，禁止连续读取同一状态并比较哈希形成恒真断言。
- 录入控制器单元测试覆盖动态字段自动扩展、删除重排后清除旧键、来源保留、编辑单次通知、历史模板版本和长期日期原值；Widget 回归保留字段输入、退出确认与编辑保存交互。
- 一条完整录入主路径、一条详情主路径和一条备份恢复主路径足够承担主集成职责。
- Widget 测试只断言用户可感知行为，不冻结私有 Widget 树、任意裸像素或源码字符串。布局缺陷可断言共享间距 token、自适应重排规则及不存在重复边距，但不得复制实现细节形成脆弱快照。
- 安全策略、状态机和错误映射优先使用纯单元测试。录入顺序、字段来源与自动填充规则集中在 controller 单元测试；卡片图标、摘要去重、银行卡显示与显式时间集中在 builder 单元测试。Widget 套件保留关键交互与跨页面一致性，不再重复旧录入顺序或同一合并入口。
- 屏幕内容保护测试通过三档偏好、敏感页面信号和生命周期状态验证最终前台安全窗口决策；必须区分短暂前台失焦 `inactive` 与真正后台 `hidden／paused／detached`，验证「不限制」不会因系统截图控件短暂失焦而重新开启安全窗口，且真正后台的任务快照保护不改变前台截图策略。Android 原生层须编译验证 Android 13+ 任务快照专用 API，以及 Android 12L 及以下在 `onPause` 启用 `FLAG_SECURE` 并在 `onResume` 恢复前台策略；真机专项仅以虚构资料检查任务内容不泄露，不依赖厂商文字或平台像素快照。Widget 测试只验证用户可见选项、风险确认和选择结果，不依赖源码字符串或平台像素快照。
- Manifest 和最终构建产物审计保留为平台专项。
- 首发保留空间不足时的失败提示与残包拒绝回归，沿用既有真实 I/O 错误证据；Android 独立限容量文件系统耗尽专项按用户决定跳过，不作首发阻塞，也不记为通过。不得因此移除现有导出失败或恢复原数据保护。

## 数据库生命周期

- 每个测试创建自己的数据库实例。
- 测试根组件复用该实例，不从同一个 opener 再创建实例。
- `tearDown` 必须关闭数据库并清理临时目录。
- Registry、缓存、监听器和图片 provider 必须恢复初始状态。
- 物理清空本机资料的回归必须先关闭旧数据库，再验证应用根节点替换整个依赖树；旧页面不得残留，新的备份恢复入口只能使用新数据库。

恢复日志测试必须覆盖：目录已切换但数据库未提交时回滚旧附件，数据库已提交时保留新附件，以及日志损坏时阻断启动。

解密图片缓存测试必须覆盖容量上限和淘汰时的明文字节清零。缓存预览解码失败还须覆盖派生磁盘缓存失效、新会话重建，以及清理延迟时错误提示可见、重试暂时禁用，清理失败后仍能主动重试原图；原始附件不得改变。平台编解码验证使用隔离的合成图片与临时目录，不读取既有资料或初始化应用数据库。

原生键盘走查使用真实点击和系统返回，并在测量输入内容与主操作可见性时分别确认 IME 仍然展开；程序请求焦点不能代替键盘已经显示的证据。模拟可用尺寸的布局矩阵、真实 Activity 旋转和系统键盘结果分别记录，不相互代替。密码页的极低高度回归同时覆盖输入焦点保留及收键盘后的返回入口恢复，只使用空输入或隔离夹具。窗口焦点与输入连接条件见 [Android 输入法可见性说明](https://developer.android.com/develop/ui/views/touch-and-input/keyboard-input/visibility) 。

模拟器以 `-read-only -no-snapshot` 保护既有 AVD 数据，临时验证入口只访问自己创建的目录；结束后覆盖安装正常应用入口。使用临时入口验证生产 V3 服务时，数据库目录、附件、备份历史与凭据必须隔离，密钥和密码只在内存中随机生成，不读取既有应用资料。容量回归使用生产密码派生参数，分别核对附件内容、跨密钥重新加密、原件不变、数据库重新打开，以及失败后活跃资料与 staging 状态；它不代替 SAF 提供方、真实磁盘耗尽或进程中断后的系统恢复验收。

Linux 上单独设置 `TMPDIR` 不足以保证模拟器临时磁盘离开 `/tmp`。若出现配额耗尽，按进程指定 `ANDROID_TMP`，并核对实际打开的临时磁盘位置，不修改系统临时目录或 AVD 配置。示例在已忽略的 `build/` 下创建临时目录：

```bash
mkdir -p build/anch-emulator-tmp
env ANDROID_TMP="$PWD/build/anch-emulator-tmp" TMPDIR="$PWD/build" \
  "$ANDROID_SDK_ROOT/emulator/emulator" -avd Pixel_10 \
  -read-only -no-snapshot -no-audio -no-boot-anim -no-window
```

`Pixel_10` 仅为本机示例，执行前先盘点实际 AVD；`ANDROID_TMP` 的用法参见 [Android 官方 acloud 启动实现](https://android.googlesource.com/platform/tools/acloud/+/46347a9783a9300340f048ba199776e433e46d61/create/goldfish_local_image_local_instance.py) 。Profile 帧时间应在预热后记录构建／栅格化分位数和超帧预算数量，模拟器结果仅作同环境基线；应用内字号、原生旋转、真实分屏和系统字号必须分别注明范围，不能互相代替。

加密附件缩略图测试必须覆盖缺失文件时的脱敏失败态，且不得断言或显示完整文件路径。

## 当前基线

最新测试数量、耗时和构建结果以 `ROADMAP.md` 为准。默认套件覆盖 V9 来源迁移与备份兼容、归档／续保规则、流式分帧认证与最终提交拦截、附件来源 ID 对齐、私有 staging 原子恢复、恢复重试与会话清理、导出真实字节进度、屏幕内容保护、石墨资料册主题、自适应导航、页头新增入口与设置安全说明的关键行为。测试成功路径不得出现 Drift 多数据库实例警告、未声明标签警告和调试输出。

搜索回归必须覆盖先查空尾号再新增、尾号修改、归档与删除后恢复、超过 100 条候选的筛选、银行别名，以及统一摘要白名单排除完整字段和原始快照。应用锁存储回归必须区分缺失记录与损坏／读取失败，验证校验前持久化尝试、写入失败不执行校验、并发去重，以及冷却期间生物识别仍可点击。

恢复清单回归必须覆盖：V1 与 V2 密码错误时清空密码但保留同一前台会话已选文件，下一次输入可直接重试；V2 重试必须重新打开同一 SAF 只读流，不缓存整份文件、持久化或输出 URI。V1 与 V2 认证成功后按成员展示资料标题、类型、状态和附件数量；清单应在窄窗口使用可用宽度、内容可滚动且操作保持可见。结果和预览模型的 `toString` 不得包含成员名称、标题、字段值、附件内容、密码或路径；恢复仍须经一次整包覆盖确认，不得出现选择性恢复入口；整包覆盖期间必须显示共享、不可关闭的全屏遮罩并阻断重复操作，遮罩文字须具有 Material 样式边界，完成后立即移除；清单或覆盖确认处于前台时进入后台，必须关闭对话框、清除已认证会话并要求重新选择文件，不能继续应用已认证结果。

备份密码页生命周期回归还必须区分 `inactive → resumed` 与真实后台：前者不得清空导出／恢复密码、关闭 V2 恢复进度遮罩或显示「安全保护已生效」；`hidden／paused／detached` 往返仍必须按既有安全规则清除敏感会话。系统文件选择器往返和真实后台均需分别覆盖。

导出页面回归必须使用可控异步回调验证：选择保存位置前不显示进度遮罩；目标写入会话建立后显示共享、不可关闭的全屏确定进度遮罩，百分比随实际写入推进，页面点击、顶部／系统返回和重复提交均被阻断；原生保存确认前不显示 100%，回调以成功或失败结束后，遮罩必须在结果对话框出现前移除。共享遮罩还须在隔离 Widget 夹具中验证 Material 文字样式边界，避免 Flutter Debug 回退的黄色双下划线。测试验证可感知行为和语义，不依赖源码字符串或像素快照。

### 备份容量手动基准

容量边界评估时手动执行：

```bash
fvm flutter test benchmark/backup_capacity_benchmark_test.dart --reporter compact
```

该基准只在内存中生成虚构附件，覆盖 V1 附件 Base64、生产 PBKDF2 参数下的加密、50 MiB 外层文件编码上限和解密预检。它不读取文件、不接触真机资料，也不进入默认套件。输出的 RSS 仅用于同机趋势比较，不能替代 Android 真机、SAF 保存或恢复 staging 的峰值测量。

### 生产 V2 自动化回归

默认套件必须覆盖 V2 的有限帧写入、随机 salt／nonce 前缀下的认证往返、篡改拦截、无最终提交帧拦截、附件来源按 ID 对齐规范 manifest、缺失或长度不符的整体失败，以及「流式解密 → 私有附件 staging → 原子附件切换与数据库覆盖」闭环。测试只生成运行时虚构字节与临时目录；不得在源码、日志或断言中记录备份密码、附件内容或完整路径。

### 隔离流式备份真机基准

流式基准只能由独立 `:streaming_benchmark` Android 模块运行，使用独立应用 ID、独立原生 Activity 与虚构字节生成器；不得初始化或读取生产应用的数据、数据库、附件目录、PIN、备份密码或签名口令。基准容器必须覆盖「流式导出 → SAF 保存 → SAF 流式读取 → 分帧认证与顺序校验 → staging 模拟恢复」的完整往返，且包含取消或写入中断后的无最终提交帧拦截回归。

真机报告只记录档位、累计字节、阶段耗时、吞吐、内存趋势和通过／安全失败结论；不得记录文件路径、URI、字节内容、密码、密钥或真机现有资料。输出的基准文件仅含虚构字节，不由应用自动删除。

构建独立基准 APK 前，验证签名文件仍被 Git 忽略且不读取其内容；随后执行：

```bash
cd android
./gradlew :streaming_benchmark:assembleDebug
```

产物只允许以独立包名 `icu.codealive.anch.benchmark` 安装；常规 `securityValidation` APK 可按项目要求构建，但不得为了该基准覆盖安装正式应用 ID。

常规代码改动提交前执行：

```bash
fvm flutter analyze
fvm flutter test
```

需要真机人工体验时，构建受控假数据包：

```bash
fvm flutter build apk --debug --dart-define=ANCH_SECURITY_MODE=securityValidation
```

首次在开发电脑构建前，须从已建立签名的电脑安全复制 `android/validation-signing.jks` 和 `android/validation-signing.properties` 两个本地文件。两者均被 Git 排除；不得重新生成同名 keystore，否则 Android 会将其视为不同签名并拒绝覆盖安装。内部验证签名用于 Debug／`securityValidation` 与 Profile，不得替代正式 Release 签名。Profile 必须显式绑定该签名，不能依赖 Flutter 在应用配置前复制的默认 Debug 配置；安装前应核对其证书与正常内部验证包一致。

### 正式 Release 签名

自用正式版、私下分发 APK 与后续 Google Play 上架必须从首个正式版本开始使用同一把长期 App Signing Key。正式 keystore 与密码文件保存在项目外的私有目录；仓库只保留 `android/release-signing.properties.example`。本机复制为 `android/release-signing.properties` 后填写 keystore、密码文件的绝对路径和固定别名；真实配置文件已被 Git 排除。

执行 Release 任务时，配置、keystore、密码文件或字段任一缺失都会在 Gradle 配置阶段失败，不得回退到 Debug 或内部验证签名。Debug／`securityValidation` 构建不依赖正式签名配置。第二台开发电脑不得重新生成正式 keystore，必须通过离线介质安全复制同一份 keystore 与密码文件，并在本机重建未提交的路径配置。

首次从 `securityValidation` 安装切换到正式签名时，Android 会因证书不同拒绝覆盖安装。只能先导出虚构备份，卸载验证包，再安装正式包并恢复；不得复用内部验证签名绕过该边界。上架 Google Play 时以现有 App Signing Key 接入 Play App Signing，再单独建立 Upload Key。

附件与本机密钥相关改动发布前，使用正式签名正常入口及虚构资料检查保存后读取、进程重启后读取、覆盖升级后读取，以及 V3 备份在重建测试资料空间后的恢复和再次重启。升级基线与候选须实际为不同构建，应用标识及长期签名保持，不能用重装同一 APK 代替升级。自动化覆盖非法存储值不覆盖、读取失败不生成密钥，以及平台调用禁用自动删除选项；不在日常手机上破坏真实密钥制造故障。开发遗留资料允许弃用时另记授权，不以弃用或空库启动作为附件可靠性通过证据。

### 跨开发电脑转移内部验证签名

使用本人保管的 U 盘转移时，只复制以下两个文件，可在 U 盘中放入单独的 `anch-validation-signing` 目录，避免与其他项目签名混放：

```text
android/validation-signing.jks
android/validation-signing.properties
```

不得复制到 Git 仓库历史、普通聊天、邮件附件或未加密的公共网盘。U 盘应始终由本人保管；转移完成后由主人决定继续离线保管或安全清除，应用和开发命令不得自动删除 U 盘内容。

在另一台电脑先取得项目代码，再将两个文件放回项目内完全相同的相对位置：

```text
android/validation-signing.jks
android/validation-signing.properties
```

随后收紧本地权限，并确认文件仍被 Git 忽略：

```bash
chmod 600 android/validation-signing.jks
chmod 600 android/validation-signing.properties
git check-ignore -v android/validation-signing.jks android/validation-signing.properties
git status --short
```

`git check-ignore` 必须同时命中两个文件，`git status --short` 不应把它们列为待提交。不得打开、打印或记录 properties 中的口令。文件缺失、配置不完整或构建仍提示签名错误时停止构建并检查复制结果，不得重新生成 keystore、修改口令或回退到系统默认 Debug 签名。

该包仅供内部虚构数据验证，不能作为正式分发物；正式发布前仍需 Release 构建、最终 Manifest 权限审计和 Android 真机安全走查。

1. 为新出现的用户可感知问题补充最小行为回归，避免用脆弱像素／私有树结构断言替代。
2. 按目录和标签逐步建立日常／完整命令，不改变默认套件的覆盖边界。
