# 收货地址本地解析

## 目标与边界

收货地址资料只保存收件人、手机号码、所在地区和详细地址四个字段。用户在录入页主动点击「粘贴并解析」后，应用读取一次剪贴板并完全在本机解析；不得后台读取、联网解析、保存剪贴板原文或在日志和异常中输出地址内容。

解析器的目标是减少手工拆分，不是替用户保证地址正确。解析结果必须回填到可编辑表单，由用户确认后才能保存。低置信或存在歧义的字段宁可留空，也不得静默猜测。

## 实现边界

解析器位于 `lib/core/service/shipping_address_parser.dart`，采用字段标签、手机号规则、三级行政区候选树与评分，支持受控别名、层级省略、直辖市和同名区县消歧。分数或候选间安全差距不足时地区留空，字段级置信状态只用于本次回填，不持久化。

省／市／区县常量位于 `lib/core/service/shipping_address_region_data.dart`，来源为 `modood/Administrative-divisions-of-China`／`china-division` 2.7.0 的 2023-06-30 数据。原仓库 LICENSE 为 WTFPL，而包元数据声明 MIT，实际取用材料的许可与署名待澄清，见 [第三方材料](third-party-materials.md) 。运行时不联网更新，不含街道／村级全集，也不声称为实时行政区数据。

## 决策

采用 Dart 内实现的「行政区候选树＋多候选评分」，不引入在线服务、JavaScript 运行时或大型 NLP 模型。

- `libpostal` 是通用统计地址解析器，支持中文，但默认模型约 1.8 GB，并需要原生 C 集成，不符合当前 Android 离线应用的包体和维护边界。
- `zh-address-parse` 的正则与行政区树组合可作为算法参考，但它是 JavaScript 实现，仓库声明的内置行政区数据更新时间为 2020-11-20，不直接作为依赖或权威数据源。
- 行政区数据仅内置省／市／区县三级和必要别名，不引入街道、乡镇、村级全集。数据必须标注来源、版本和生成方式；上游停止更新或版本陈旧时，不得表述为实时行政区数据。
- 不增加数据库字段或迁移。解析置信度只用于本次录入交互，不持久化到资料。

参考来源（核对日期：2026-07-22）：

- [libpostal 官方仓库](https://github.com/openvenues/libpostal)
- [zh-address-parse 官方仓库](https://github.com/ldwonday/zh-address-parse)
- [中华人民共和国行政区划数据项目](https://github.com/modood/Administrative-divisions-of-China)

## 解析流程

按以下固定顺序处理，每一步保留原始字符区间，避免重复消费文本：

1. 归一化：统一全角／半角空白和常见分隔符；合并连续空白；只移除已确认的字段标签，不改写用户地址字符。
2. 标签提取：优先识别「收件人／收货人／联系人」「手机号码／手机号／电话」「所在地区／地区」「详细地址／地址」等明确标签。标签值为最高置信结果。
3. 手机号提取：支持普通 11 位大陆手机号以及带 `+86`／`86` 的常见写法；回填时规范为 11 位号码。不得把其他长数字自动改成手机号。
4. 行政区候选：从剩余文本中检索省／市／区县正式名称与受控别名，生成所有可能的上下级链。支持「浙江／浙江省」「杭州／杭州市」等后缀省略和直辖市简写。
5. 候选评分：按上下级一致性、文本出现顺序、匹配覆盖长度、正式后缀、标签边界加分；按层级冲突、重复消费、同名歧义和跨越大段无关文本减分。
6. 地区决策：仅当最高候选达到阈值且与次高候选拉开安全差距时写入所在地区；否则保留待确认状态，不凭单个同名区县猜测。
7. 收件人推断：在已消费手机号与行政区后，从相邻短文本中寻找收件人；只接受合理长度和字符组成，不把公司名、楼栋号或备注强行作为姓名。
8. 详细地址：将未消费的地址文本按原顺序合并，保留楼栋、单元、门牌、园区和公司等信息；不得对内容做模糊纠错。
9. 输出：返回四字段候选以及字段级置信状态。页面继续展示可编辑结果，并用简短提示要求用户核对，不自动保存。

评分值和阈值应封装为解析器内部实现细节，通过语义明确的候选对象和行为测试约束，不在页面复制评分规则。第一版只做受控别名匹配，不做拼音、OCR 或机器学习。

## 数据组织

行政区数据应作为可审查的静态资源或生成后的 Dart 常量进入 `lib/core/`，不得在 UI 层维护地名列表。生成脚本若需要保留，应放在项目已有工具目录；若必须新增目录，先更新 `AGENTS.md` 的工程结构约定。

数据至少包含：

- 稳定行政区代码。
- 标准名称、层级和父级代码。
- 去除「省／市／区／县／自治区／自治州」后的受控别名。
- 直辖市和自治区的明确别名规则。
- 数据来源、版本日期和许可说明。

禁止自动生成单字符泛化别名。名称相同的区县必须保留为多个候选，由父级上下文消歧。

## 展示边界

详情标题首行对齐与资料图标遵循 [视觉规范](ui-visual-design.md)。地址页只使用 `AnchIcons.shippingAddress` 的语义入口，不直接引用 SVG 路径。自动化与真机确认状态见 [路线图](../ROADMAP.md)。

## 自动化验收

解析行为至少覆盖：

- 带字段名的四行地址，以及字段顺序变化。
- 无标签单行、多种空白和中英文分隔符。
- `+86`／`86` 手机号与普通 11 位手机号。
- 省市区后缀完整、省略后缀、省略省份或城市。
- 北京、上海、天津、重庆直辖市。
- 自治区、自治州和名称较长地区。
- 同名区县有完整上级、上级缺失两种情况；缺失时不得高置信猜测。
- 收件人在地址前、手机号前后以及无法可靠识别。
- 楼栋、单元、房号、园区、公司名称和数字混合的详细地址。
- 非地址文本、缺少手机号、缺少地区和空剪贴板。
- 解析全程不触发网络、不持久化剪贴板原文、不在可见错误中回显整段输入。

完成标准：新增行为测试通过，现有收货地址新增、回填、保存、详情唯一复制入口和四行复制格式不回退；静态分析、完整测试、APK 构建与虚构资料真机确认均完成后，才能在 `ROADMAP.md` 标记完成。
